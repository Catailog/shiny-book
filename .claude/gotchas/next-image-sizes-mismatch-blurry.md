# next/image의 sizes를 실제 렌더링 폭보다 작게 주면 화질이 흐려짐

`<Image fill sizes="200px" />`처럼 `sizes`에 실제 CSS 렌더링 폭보다 작은 값을 주면, Next.js가 그 값 기준으로 srcset을 생성해서 실제 필요한 해상도보다 작은 이미지를 받아온다. 브라우저는 받아온 작은 이미지를 실제 박스 크기(`fill` + `object-cover`)로 그대로 늘려서 그리기 때문에 화질이 흐릿하게 보인다. 타입 에러도, 콘솔 경고도 없어서 "그냥 원본 이미지 화질이 안 좋나 보다"고 착각하기 쉽다.

grid/flex 레이아웃 안에서 이미지 폭이 padding/gap을 뺀 값으로 계산되는 경우(예: 2열 그리드 안의 썸네일) 실제 폭을 감으로 넣기 쉬운데, 대략적인 수치가 아니라 실제 폭에 최대한 가깝게 넣어야 한다.

## 해결

`sizes`에는 그 이미지가 실제로 화면에서 차지할 CSS 폭을 반영한다. 컨테이너의 padding/gap을 뺀 값으로 계산하고, 반응형 브레이크포인트가 있으면 `sizes="(min-width: 1024px) 260px, 45vw"`처럼 구간별로 명시한다.

`src/app/(marketing)/hero.tsx`의 세로 마퀴 책 이미지 썸네일에서 이 문제를 겪었다(칼럼 실제 폭 약 258px인데 `sizes="200px"`로 지정해서 흐리게 보였음).
